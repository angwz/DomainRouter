## 1. 项目目标与范围

DomainRouter 是开源的、供用户维护个人分流配置的规则编译工具。当前用户在自己的 VPS 上运行自维护的 subconverter，生成 Clash Meta/Mihomo 订阅，并使用 fake-ip 模式；这套环境是首个兼容目标，不是其他使用者必须拥有的账号或地址。

DomainRouter v2 负责：

1. 读取 `my.wei`，解释合集、混合规则输入和底部 `[Rules]` 的匹配顺序。
2. 获取、解析并整合外部规则源。
3. 在不改变有效匹配行为的前提下去重、消除包含项、精确合并、规划输出和排序。
4. 每个合集发布最多三个非空规则资源：domain MRS、ipcidr MRS、classical YAML。可读 YAML/文本是前两类的构建中间产物与调试资料，不是默认额外订阅资源。
5. 生成供 subconverter 使用的 `rulesets.toml`、`groups.toml`。
6. 解释修复、保留、合并、删除以及跨合集优先命中的原因。
7. 验证最终转换链路，并统一发布完整产物。
8. 必须支持每天自动刷新来源并重新生成三类规则资源及配套配置；每日自动化是核心交付的一部分，具体见第 15.5 节。

本轮核心范围不包括 Shadowrocket、dnsmasq、Xray、其他客户端模板，也不负责实现代理内核、机场订阅协议解析或节点转发服务。旧资料保留，迁移期间不批量删除。

Web 是可选的编辑与预览界面。AI 是可选的建议模块。没有浏览器、数据库、AI API key 或常驻服务时，核心构建必须仍能完整运行。

## 2. 已确认的决定与正确性边界

| 事项 | 确定要求 |
| --- | --- |
| 主要输入 | 继续使用 `my.wei` |
| 裸域名 | 手写 `a.hk` 包含自身及所有层级子域名 |
| 单引号 | 手写 `'a.hk'` 按原模式匹配，不隐式扩展子域名；单引号内允许通配模式 |
| 显式规则 | `DOMAIN,a.hk` 精确匹配；其他显式类型遵守其类型语义 |
| 未加引号的通配模式 | 对该模式原有匹配结果增加子域名闭包，不能扩大到原模式的父域名 |
| 合集内部 | 成员表示同一合集的匹配条件并集，不在原始行中嵌入独立出口优先级 |
| 全局优先级 | 以 `[Rules]` 的原始顺序为准，包含内联规则的位置 |
| 产物数量 | 每个合集 0～3 个非空发布资源：domain/ipcidr 用 MRS，classical 用 YAML；0 个时须按空合集规则处理 |
| IP 策略 | 默认让目标 IP 类分流条件不主动触发域名解析，即应用 `no-resolve` 策略 |
| 主要转换方式 | 最终订阅保留原生 provider；domain/ipcidr 必须声明 `format: mrs`，classical 声明 `format: yaml`；使用第 12 节的格式桥接 |
| 跨合集优化 | 默认分析重叠和遮挡，不从可独立使用的合集产物中删除成员 |
| 原始内容 | 构建不得覆盖或重写 `my.wei` 的原文、注释和输入来源 |
| 正确性基线 | 以 v2 已确认语义及项目策略为准，不能把 v1 的错误输出作为标准答案 |
| 自动生成频率 | 每天一次刷新、生成与验证；发布启用后，成功结果以整套 generation 更新，失败保留上一版 |

“最优”按以下顺序评估：匹配与路由正确性、分流过程的 DNS 行为、实际匹配成本、加载和内存成本、文件体积与可读性。不得仅用删除行数证明运行效率提升。

核心保证覆盖原生域名模式与 CIDR 的规范化、常规包含消除和精确合并。对任意复杂正则、逻辑表达式以及跨类型的全局最少条数，不承诺无法证明的最优解；必须明确保留原因或分析限制。

## 4. 输入语法：my.wei

### 4.1 文档结构

使用逐行词法分析与有状态解析，保留原文位置。禁止用一个跨文件正则表达式按任意 `[` 切分全部内容。

```text
[Example]
# 手写规则、资源引用和粘贴的规则块
a.hk
'status.a.hk'
DOMAIN,api.example.com
192.0.2.0/24
https://example.org/rules.yaml

[Rules]
Example: 🌠 节点选择
GEOIP,CN: DIRECT,no-resolve
MATCH: 🐳 漏网の鱼
```

- 只有符合完整节标题语法的独立行才开始新节。规则、正则中的方括号不是节边界。
- 节标题必须从行首开始，格式为 `[名称]`，其后只允许空白或明确注释；名称非空、无控制字符及 `[]`。结构化块内按该块语法解析，不识别新的自由行节标题。未知的自由行单标签/字符类表达式不得凭猜测当成域名。
- `[Rules]` 是精确识别的保留节名，不能把所有名字含有 `rules` 的合集跳过。
- 合集名称保留大小写并精确引用；不因大小写归一化合并两个名称。
- 同名合集重复声明：按出现顺序合并成员，给出可定位的提示；重复 `[Rules]`：报错。
- 自由行按原始出现顺序记录来源；并发下载完成顺序不得改变来源顺序。
- 结构化粘贴块必须有可判定的边界，按第 4.7 节解析；不能把后续所有行都交给 YAML，也不能每遇空行就终止块。
- 文本文件按 UTF-8 读取，接受 BOM、LF/CRLF；文本输出统一 UTF-8 无 BOM、LF、末尾一个换行。MRS 二进制不采用文本换行/编码规则。
- 构建只读取原文。将来 Web 编辑采用显式修改操作，保留未修改部分。

### 4.2 域名、单引号和通配符

下表是必须直接成为测试数据的手写语义：

| 手写输入 | 规范化匹配含义 | 原生 domain 输出示例 |
| --- | --- | --- |
| `a.hk` | 自身及全部子域名 | `+.a.hk` |
| `'a.hk'` | 仅自身 | `a.hk` |
| `"a.hk"` | 双引号只是外围容器，仍使用默认扩展 | `+.a.hk` |
| `DOMAIN,a.hk` | 仅自身 | `a.hk` |
| `DOMAIN-SUFFIX,a.hk` | 自身及全部子域名 | `+.a.hk` |
| `'*.a.hk'` | 恰好一级子域名，不含自身 | `*.a.hk` |
| `*.a.hk` | 一级子域名及其所有下级，不含自身 | `.a.hk` |
| `'.a.hk'` / `.a.hk` | 所有子域名，不含自身 | `.a.hk` |
| `'+.a.hk'` / `+.a.hk` | 自身及全部子域名 | `+.a.hk` |
| `'xbox.*.example.com'` | 中间一个完整标签通配，不额外扩展 | `xbox.*.example.com` |
| `xbox.*.example.com` | 前一模式及其全部下级域名 | `+.xbox.*.example.com` |

上表的 domain 输出是送入 MRS 编译器前的可读表示；正式发布文件为 `.mrs`，二进制格式不改变这些语义。固定标签使用实际 literal 值；表内 ANY 只是模型说明，不是可直接输出的字符串。

单引号约束的是匹配范围。若该条已经被同合集另一条完整覆盖，仍允许从生成产物中省略，原文保留。

解析优先级必须明确：先识别显式规则类型和结构化块，再对自由域名行应用单引号及默认扩展。`DOMAIN,*.a.hk` 不得自动变成通配规则；按显式 `DOMAIN` 的目标语义校验，无法满足输入意图时给出错误与修正建议。

原生 Clash 域名通配与显式 `DOMAIN-WILDCARD` 不是同一语言：

- 原生 `*` 匹配一个完整标签，原生 `+`/前导点处理层级后缀。
- `DOMAIN-WILDCARD` 的 `*`、`?` 按目标内核的字符通配语义处理。
- 原生模式不能放置的局部标签通配（如 `foo*.example.com`），必须给出明确的诊断，建议用显式 `DOMAIN-WILDCARD`；不能偷偷选择一种解释。
- 对明确指定的通配/正则规则保留其语言；转换到其他可表达形式时，必须有等价转换和目标内核测试。
- 不支持的 `**`、误放的 `+`、不平衡引号等不得简单删除符号后扩大匹配范围。
- 单独的自由行 `*`、`+`、`.` 不能当作待清理的标点，也不能默默解释成全域名规则；报歧义并要求明确写法。显式的原生全通配模式（例如单引号内的 `'*'` 或 `'+.*'`）按内核语义处理并提示覆盖范围；不能把其非空匹配集合优化成空集合。
- 单引号只改变自由域名行的隐式扩展，不能取消原生 `+.` 本身已有的后缀含义。`'+.a.hk'` 仍包含自身和下级。
- `DOMAIN-SUFFIX,'a.hk'` 等显式字段的配对引号只是该字段的包装；去除后仍是后缀类型，不降为精确类型。不要对显式规则递归套用自由行默认扩展。
- 上一项是手写 my.wei 的字段包装约定。第三方 text 只有在其格式明确支持包装引号时才去除；不能把 native text 中本来属于 literal 的单引号或其他字符套用手写习惯后当作另一条有效规则。
- `DOMAIN`、`DOMAIN-SUFFIX` 的 payload 是字面域名字段，不能把其中 `*`、`+` 或前导点偷换成 domain provider 模式。`DOMAIN-SUFFIX,*.a.hk` 不等于原生 `*.a.hk`，`DOMAIN-SUFFIX,.a.hk` 也不等于原生 `.a.hk`；首版对这类特殊 payload 报错并建议使用明确的原生 domain 块或正确规则类型。
- 空标签、标签边界和合法字符按目标支持的输入集合校验。`OTHER` 符号类、IDNA、大小写及 FQDN 修复在参考解释器与优化器中必须采用一致契约；不能先用不同的域名合法性定义证明包含，再对另一套输入宣称等价。

### 4.3 IP 与 CIDR

- 先识别 IP/CIDR，再识别普通域名，避免把 IPv4 当成域名。
- 单个 IPv4 规范化为 `/32`，IPv6 为 `/128`；外围引号不改变其地址语义。
- IPv4、IPv6 分别处理，不能混用地址长度或合并为同一网段。
- CIDR 带主机位时可按网络掩码规范化，并记录原值与新值；非法前缀、非法地址不得修剪成另一个有效地址。
- 来源地址与目标地址分开建模；`src` 参数与 `SRC-IP-CIDR` 可以在验证后规范化到相同来源条件，但绝不能进入目标 ipcidr 输出。
- IPv4-mapped IPv6、zone ID 等边界单独校验，不能未经目标内核验证就跨地址族折叠。

### 4.4 URL 和输入指令

以下是 v2 采用的输入指令形式，实施时须支持：

```text
https://example.org/rules.yaml
@source https://example.org/rules.yaml format=auto
@source https://example.org/domains.txt format=domain
@source https://example.org/personal.txt format=wei
@source https://example.org/clash.yaml format=clash-config exclude_types=MATCH,FINAL
@site https://www.example.com/path?x=1
```

- 裸 HTTP/HTTPS URL 与 `@source` 均表示下载规则源，保持已有使用习惯。
- `@site` 只提取 URL 的主机部分，不下载网页、不保留路径/端口/查询作为域名。域名默认包含子域名；IP 主机按 IP 处理。
- `format` 是解析适配器的显式选择；默认 `auto`。不允许资源下载失败后自动退化为 `@site`。
- `exclude_types` 是显式导入过滤器，值为逗号分隔的精确类型名；首版只允许排除 `MATCH`、`FINAL`。每个被排除项必须记录位置、类型和原因。未声明时仍按第 5 节对控制语句报错，不能自动丢弃完整配置中的兜底语句。
- 指令参数应由小型词法分析器处理，支持引号和 URL 查询字符串；未知参数报错。
- 禁止执行规则源中的代码、模板、shell 指令。嵌套资源引用不自动递归展开，见第 5 节。

### 4.5 Rules 节

- 合集定义的前后顺序不决定路由优先级，`[Rules]` 才决定最终顺序。
- 允许引用同一合集多次；保留每次引用及位置，不擅自去重或合并。
- 普通合集映射为 `合集名: 策略组`；内联规则为 `规则条件: 策略组[,参数]`。
- 合集引用本身首版不接受 `src`、`no-resolve` 等附加参数；其目标 IP 策略由项目和成员类型决定。将来源地址意图写为显式来源条件。内联规则只接受该类型支持的参数。
- 标准分隔符为规则表达式顶层的 `:` 后跟空白。扫描器须识别转义、配对引号、括号，以及正则的字符类与转义状态；不能把 `[a: b]` 或 `(?:...)` 内部冒号当作策略分隔符。只在对应语法允许包装时进入引号状态，正则里的字面引号不是自由行包装。简单的历史 `Example:DIRECT` 只在左侧恰为已定义合集、右侧恰为已知目标且分解唯一时接受；内联规则使用标准形式。
- 不能直接 `split(':', 1)`：IPv6 和表达式中可能有冒号。逗号也必须遵守规则类型和括号深度。
- 未定义合集、未知目标组、无效参数均报错。
- 引用名称若恰好与内联保留类型相同：有逗号的已登记类型按内联解析，无逗号的已声明合集按合集引用解析；`MATCH`/`FINAL` 永远保留。不能按名称前缀猜类型。
- `MATCH`/历史别名 `FINAL` 必须有且只有一个并位于最后；位置错误时报错，不自动搬到最后掩盖问题。
- 未被 `[Rules]` 引用的合集默认仍生成独立文件，并提示“未被当前路由使用”。
- 被引用但没有有效规则的合集默认阻止发布；有意为空必须通过项目配置明确允许，并在输出计划中省略该空引用。
- 内联规则保持原位。复杂内联规则能否经过用户 fork 无损生成，必须经过兼容门禁；不支持时报错，不静默省略。

### 4.6 脏数据与规范化修复

修复只能发生在已识别的上下文中：

- 清理 BOM、外围空白、明确的列表符号、成对的 Markdown 外包装。
- 自由行剥离列表符号后，仍保留单引号语义；完整 YAML 块的引号仅是 YAML 语法。
- 自由域名/地址 token 可以进行明确的外围标点清理；必须记录修复，不能全文件删除标点。
- 成对中文单引号规范化为语义单引号时记录修复；不平衡或不明确的引号报错，不能去掉后当裸域名。
- 域名规范化大小写和可验证的 IDNA 表示；去除 FQDN 末尾点时记录。不得把进程路径、正则、组名全部转小写。
- 行首 `#`、`;`、`//` 可作为自由行注释。行内注释只在类型适配器确认的位置识别，不能截断 URL、正则或逻辑规则。
- 不使用“顶级域名不超过六个字母”等过时校验；不依据当前 DNS 是否存在来判定语法有效。
- 不按公共后缀或品牌猜测扩大域名范围，例如不能把 `a.co.uk` 提升成 `co.uk`。

诊断级别：`info` 为明确修复/空行/注释统计，`warning` 为不影响已确定语义的情况，`error` 为疑似有效但无法处理、语义歧义或无法输出的规则。预览可以带错误结束并提供可用结果，正式构建/发布遇到 error 必须失败。

### 4.7 结构化粘贴块与字段词法

首版支持两种明确边界：

1. 推荐的显式块以独立行 `@begin format=domain` 开始，以独立行 `@end` 结束；format 使用第 5 节的适配器名，内容原样送入该适配器。块内的节标题、引号和空行属于该格式，不再应用自由行规则。块不嵌套；缺少结束标记或内部出现无法作为内容解释的独立 `@end` 时诊断，建议改用来源文件。`@begin format=classical` 等同理。
2. 为便于直接粘贴，行首 `payload:` 或 `rules:` 单独起一个隐式 YAML 块，只接收后续缩进的序列项及其续行、空白和注释；首个非空、非注释且回到列 0 的行结束该块，并重新交给 my.wei 解析器。无缩进序列、完整多键配置、多个 YAML 文档以及复杂多行内容必须使用显式块或 `@source`，不能推测边界。块必须能独立解析成对应的单键映射。

例如 `@begin format=domain`、`payload:`、缩进的 `- '*.a.hk'`、`@end` 组成一个原生 domain YAML 块；这里的单引号仅是 YAML 容器，仍为恰好一级子域名。孤立自由行 `- '*.a.hk'` 则先剥离列表标记，再应用手写单引号约定。无语言声明的 Markdown 代码围栏不自动选择格式；可诊断并建议使用上述显式块，不将围栏内未知内容逐行吞掉。

字段解析必须按类型区分普通标量、正则、路径和复合表达式。仅对登记为普通标量的字段去除配对包装引号；正则中的单引号、反斜杠、字符类等是语言内容，不进行通用 trim/unwrap。规则语法不是任意 CSV：若含逗号的 payload 不能由目标内核的解析入口无损表达，报告 `E_BACKEND_LOSSY`，不发明 CSV 引号规则。原文可被词法器读取，不等于该规则可以被目标后端执行。

## 5. 上游规则适配器

核心首版的格式支持矩阵：

| 格式 | 核心阶段要求 | 处理约定 |
| --- | --- | --- |
| `wei` | 必须 | 明确指定后使用本项目自由行语义；不允许递归下载其中的 URL |
| Clash domain YAML / `format=domain` | 必须 | 裸域名精确，原生通配保持；不套用 my.wei 默认扩展 |
| Clash ipcidr YAML / `format=ipcidr` | 必须 | 地址/网段规范化，再应用项目参数策略 |
| Clash classical YAML / `format=classical` | 必须 | 按已登记类型解析 |
| Surge/Clash 风格文本规则 / `format=surge` | 必须 | 支持经过验证的规则类型、参数及可选原出口字段 |
| 完整 Clash 配置 / `format=clash-config` | 必须支持有明确过滤的提取 | 只将 rules 及相关 provider 元信息加入规则模型；原出口被记录并剥离，MATCH/FINAL 需显式 exclude_types；不将节点凭据用于构建或导出 |
| 无包装文本域名列表 | 必须可指定格式 | `domain` 表示精确原生列表，`wei` 表示项目默认扩展；auto 不猜含义 |
| QuanX、hosts、Adblock 等 | 可选后续适配器 | 未实现时报明格式；不能当垃圾逐项吞掉后报告成功 |
| 外部 MRS 输入 | 可选后续适配器 | 首版输出 MRS 不等于已支持导入任意 MRS；遇到二进制输入明确诊断，不能按 UTF-8 文本修剪 |

`format` 是适配器，不是输出文件格式。`domain` / `ipcidr` 明确允许单个 payload YAML 映射或逐行 text 两种容器，两者使用同一原生 behavior；`classical` 处理 payload YAML，`surge` 处理显式规则文本，`clash-config` 处理完整配置，`wei` 处理本项目自由行。容器识别后必须整体解析；不能在结构化解析失败后退回逐行猜测。除 `clash-config` 外，不允许混入未定义的顶层配置键。

`auto` 的规则：优先识别结构化 YAML/完整配置，再识别已知显式文本规则。只有 `payload` 时，在唯一可识别的前提下，纯 CIDR 归 ipcidr、纯显式条件归 classical、纯合法原生域名归 domain；混杂或可被多种适配器接受时要求显式 format。例如全是没有掩码的 IPv4 字符串，可能是域名 literal 也可能是地址，不能仅凭“看起来像 IP”替未知 provider 指定 behavior。全是裸域名的无包装 text 在 domain/wei 间有歧义，必须指定。HTTP Content-Type、URL 路径和扩展名只能作为提示。

粘贴在 `my.wei` 中的完整 `payload:`/`rules:` 块按结构化块处理。裸列表项单独出现而没有结构化包装时，仍属于自由行上下文。报告必须展示使用了哪个适配器。

YAML 必须使用安全解析器，检测重复键并限制节点/嵌套数量；首版规则源不接受 YAML 别名、锚点、merge key、自定义 tag 或多文档输入，给出明确诊断，不能依赖 safe_load 就假定资源受限。payload/rules 必须是字符串序列；不能先把布尔值、整数、null 转成字符串掩盖错误。输出中的通配符、IP 和规则都应作为字符串，避免 YAML 隐式类型转换。生产完整 base 如需 YAML 锚点，应先由用户显式展开为普通结构，不混入规则源的容错流程。

导入规则中的原出口不是合集成员的最终出口：解析器提取匹配条件和参数，记录被剥离的原出口，最终由 `[Rules]` 指定出口。不能用简单的“第三个逗号后全部删除”，因为那里也可能是 `no-resolve` 或嵌套表达式。

完整配置通常包含 MATCH，必须支持上述显式排除路径才能完成有用提取。排除是用户声明的导入范围，不是对原配置完整路由脚本的等价优化。完整配置原始快照可能含敏感字段，默认只存本地受控缓存，不进入公开构建产物或测试快照；解析器读取结构不代表允许发布 proxies 内容。

`MATCH`、`RULE-SET`、`SUB-RULE` 等控制/引用语句不能直接放进普通 classical provider。首版遇到未显式排除的 MATCH/FINAL 或任何未解析的命名引用时必须报错。`exclude_types` 不支持排除引用语句来伪造完整导入成功。自动递归展开引用是后续能力，必须另有循环检测、深度/大小限制及等价性设计；首版建议直接导入该引用实际指向的资源。

规则类型通过注册表精确识别：类型名、字段结构、参数、能力、目标支持状态和输出后端明确登记。禁止用 `startswith('DOMAIN')` 判断所有域名类型是否合法。未知类型和目标版本不支持的已知类型分别诊断。

### 5.1 首版类型与能力注册表

最低必需类型为 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、DOMAIN-WILDCARD、DOMAIN-REGEX；IP-CIDR/IP-CIDR6、SRC-IP-CIDR、IP-SUFFIX/SRC-IP-SUFFIX；GEOIP/SRC-GEOIP、IP-ASN/SRC-IP-ASN、GEOSITE；SRC-PORT、DST-PORT、NETWORK；PROCESS-NAME、PROCESS-PATH、UID；AND、OR、NOT，以及仅顶层可用的 MATCH（输入别名 FINAL 规范化为 MATCH）。其他类型可以增量支持，但不能用一个很小的注册表就宣称核心已完成。特定平台无法执行进程/UID 时，能力报告必须注明平台并拒绝不受支持的生产目标，隔离测试不能虚构查询成功。

每个注册项至少声明：payload 解析与校验、允许的参数/原出口位置、方向、是否可能查询或改变元数据、外部数据依赖、可用后端、目标版本和平台约束、最少一个目标内核正反例。目标 IP 类型只接受目标实际支持的 `src`/`no-resolve` 参数并规范化方向；显式来源类型使用自身语义。其他类型不默认接受这两个参数；AND/OR/NOT 不接受用尾部标志代替叶节点参数。未知或重复冲突的参数报错，`no-resolve` 的重复相同声明规范化成一份并记录。

目标组名与参数关键字相同而导致来源规则字段歧义时，要求来源显式格式或报错，不按第三个字段一律当组名。控制/引用类型即使被内核支持，也不能自动成为普通 provider 成员。

## 6. 下载、快照与可重建性

下载层与解析/优化层分离。核心模型和算法不得自行联网。

- 每个唯一资源请求去重；同 URL、相同请求/授权上下文的不同解析格式共享原始字节，但使用独立适配结果。不能跨不同授权上下文共享私有响应。
- 配置连接/读取/总时限、并发数、重试和响应大小上限；默认实施值可取并发 8、最多 3 次尝试，并在测试后固定。
- 识别非成功响应、HTML 错误页、截断或超限内容；HTTP 200 不等于有效规则。
- 原始内容先按字节保存。文本适配器严格解码其声明/约定的编码，不用替换字符吞掉解码错误；MRS 或其他二进制不能进入文本修剪流程。
- 保存原始内容的 SHA-256、获取时间、最终地址、HTTP 校验信息、格式和来源标识。敏感请求头不写入报告。
- 已接受的内容按哈希保存，`sources.lock.json` 记录使用的精确快照。更换快照是明确操作。
- `fetch` 负责联网刷新；`fetch --locked` 只补齐旧锁缺失的对象并核对原哈希，不更新锁。`build --locked` 只使用锁定内容；离线重建不因远端更新而漂移。
- `fetch` 刷新失败默认不替换锁；显式允许旧快照时必须配置最大陈旧秒数，在本次 fetch/发布的时间点核验并标记 stale。旧锁仍是独立可用的锁，刷新失败不能悄悄伪装成成功获取了新内容。纯 `build --locked` 不根据当前时间改变匹配产物或拒绝曾经有效的历史锁；需要新鲜度门禁的发布任务在运行报告中单独判断，不能破坏历史离线重建。
- 失败下载与合法空内容必须是不同状态。被路由引用的合集不能因资源失败而被当作空合集发布。
- 并发结果按声明的来源位置合并；完成顺序、线程调度、字典遍历顺序不决定产物。
- 不扫描 VPS、用户内网或本机文件。HTTP 下载范围由配置确定；重定向受同样限制。供 Web 使用时不能把任意 URL 下载器暴露成匿名公共服务。

常规性能测试和离线测试使用可分发的小型快照或合成数据。保留上游来源及许可标记；不把未审阅的完整第三方数据随代码测试包发布。

`sources.lock.json` 必须有 schema_version，并记录稳定 source ID、解析选项、内容哈希、缓存对象引用和审计获取信息。原始对象默认在 `.cache/domainrouter_v2/objects/sha256/<hash>`，用户可配置缓存根。公开锁不能代替内容：新机器缺少对象时，build 必须报缺失；显式 fetch 可以尝试获取并验证相同哈希，但远端内容已变时不能声称重建了旧快照。可再分发的小 fixture 随仓库提供；真实快照另行归档及记录获取方式，不自动上传含凭据的 URL、请求头或完整配置。
